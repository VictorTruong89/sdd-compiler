## 1. Goal & why

**Store the spec graph as plain, git-friendly text, and serve it in two forms derived from that one
record** (D10):

- **Full form, for AI agents:** complete node, link, term and conflict records, reachable through
  deterministic queries without reading the whole graph.
- **Collapsed form, for humans:** aggregated by family and layer, with drill-down, as CLI text and
  generated Markdown views.

Because both forms are generated from the same records, they cannot disagree. The graph also keeps a
**registry of all conflicted nodes** (D9), so an agent finds every conflict in one read.

## 2. Scope / non-goals

**In scope**
- `.sdd/` layout for graph records.
- Store API with atomic writes.
- Consistency checks.
- In-memory indexes.
- Conflicted-node registry.
- Full-form queries (`sddc query …`) and collapsed-form commands (`sddc map`, `sddc family`,
  `sddc conflicts`).
- Generated Markdown views.

**Non-goals**
- ✗ Context recipes, manifests and traversal for code generation → F7 (G3.3). F4 provides the
  primitives those use.
- ✗ Candidate generation → F5.
- ✗ HTML viewer `sddc view` (P-14 V1–V7 as an interactive page) — built only if time allows, as its
  own spec.
- ✗ SQLite cache (P-13) — deferred; in-memory indexes suffice for rel01 volumes (⚑ D3).

## 4. Behaviour

### 4.1 Layout (P-13)

```text
.sdd/
  profile.yaml                 hand-edited (F1 CT-1.4, F3 CT-3.4)
  graph.meta.json              versions, source hashes, counts (CT-4.1)
  sources.jsonl  blocks.jsonl  runs.jsonl        (F1)
  terms.jsonl                  one term per line, sorted by id
  nodes/<family-file>.jsonl    one node per line, sorted by id
  edges/<family-file>.jsonl    links stored with the family of their `from` node
  conflicts.jsonl              conflict records (F2 CT-2.4), sorted by id
  conflicted_nodes.json        the registry (CT-4.2)
  lock/<kind>.jsonl            judgment lock (F3)
  run.lock                     held while a run writes (F1 §4, 15 s wait); not `lock`, which is the judgment lock's folder
  review.jsonl                 review queue (F3)
  views/                       GENERATED Markdown, do not edit (§4.6)
```

- `<family-file>` is the term id with `term:` removed.
- Nodes with family `(global)` go to `_global.jsonl`; family `null` goes to `_unplaced.jsonl`.
- A node whose family changes moves between files in the same transaction.

### 4.2 Writing

- All writes go through one **transaction**:
  - collect changes;
  - validate every changed record against F2;
  - recompute derived fields (status, `related_conflict_nodes`, the registry, meta counts);
  - write temporary files;
  - rename all of them;
  - regenerate views.
- On any failure nothing is renamed (reuses F1's lock and atomic-rename behaviour).
- **Determinism:** UTF-8, fixed key order, lines sorted by id, `\n` endings. `graph.meta.json` holds no
  timestamps. The same records always give the same bytes.

### 4.3 Consistency checks (every transaction, and `sddc check`)

| Check | Rule |
|---|---|
| Unique ids | No duplicate node, term, conflict or judgment id, and no two links with one key `(from, type, to)` (F2 §4.8; I-89) |
| Links resolve | Every link's `from` and `to` exist (a term, a node, or a scope) |
| Status derived | Every node's `status` equals F2 `derive_status` |
| Conflict membership | Every open conflict record's members list it in `conflict_ids`, and vice versa |
| Registry derived | `conflicted_nodes.json` equals the set of nodes with status `conflict` |
| Shard placement | Every node is in the file matching its family |
| Judgment references | Every `judgment` id referenced exists in the lock |
| Counters monotonic | Every `id_counters` value is ≥ the highest id ever issued for that family, and never decreases between transactions (rel01 D24) |

A failing check aborts the transaction (exit `4`) naming each violation. `sddc check` reports all
violations and exits `4` if any exist.

### 4.4 Indexes (P-10), built in memory on load

`by_id`, `by_term` (term id and each alias → node ids), `by_family`, `by_layer`, `by_component`,
`by_status`, `by_source` (file → node ids ordered by line), `edges_out`, `edges_in` (per link type),
`by_keyword` (keyword → node ids). Deleted nodes are in no index: they no longer exist (F2 §4.9).

### 4.5 Full form — AI queries (`sddc query`, JSON only)

| Query | Returns |
|---|---|
| `query node ID` | The node record plus its `edges_out`/`edges_in` (level 2) |
| `query source ID` | Verbatim spans, file, lines, heading path (level 3) |
| `query family TERM` | Member node records grouped by layer, the family's constraints in scope, related families via `uses_term` |
| `query neighbors ID --type T --dir in\|out\|both --depth N` | Node ids with the link path to each |
| `query conflicts` | The registry, then every open conflict record with full member records |
| `query map` | Families × layers counts and status counts (level 0, as JSON) |

- Every query output carries `graph_hash`, the hash of all record files, so an agent can tell whether
  the graph changed between two reads.
- Unknown ids exit `2`.

### 4.6 Collapsed form — human views (D10, P-14)

**CLI text** (the default without `--json`):
- `sddc map` — a table of families (rows) × layers (columns). Each cell shows the node count and a
  status mark: `✓` all validated, `?` any ambiguous, `~` any stale, `·` any unchecked, `✗` any conflict,
  using the worst status by F2 precedence. Rows sort by open conflicts, then by name.
- `sddc family TERM` — the member nodes by layer, one line each: id, status mark, and the first 80
  characters of the text. Constraints in scope and related families follow. Within a layer, lines
  follow the source (D13). Constraints in scope are lines like the members (D14). A card names its
  broader and narrower families (D15), and an ambiguous line names its ambiguity kinds (D16). `TERM` may
  be `(no family)` or `global`, the two non-family rows of the map.
- `sddc conflicts` — the end-of-run view of every open conflict (rel01 D26): id, kind, members with
  source file and line, rationale. Interlinked conflicts (sharing a member) are grouped together.

**Generated Markdown** (`.sdd/views/`, regenerated on every transaction, header
`<!-- GENERATED by sddc — do not edit -->`):
- `map.md` — the same table as `sddc map`.
- `families/<family-file>.md` — the same content as `sddc family`, with node ids linking to their
  source file and line.
- `conflicts.md` — the same content as `sddc conflicts`.

**Drill-down path:** map → family → `sddc show`/`query node` → source.

## 5. Contracts

**CT-4.1 — `graph.meta.json`**
```json
{ "schema_version": "graph/1", "compiler_version": "string",
  "question_schemas": {"q-atom": "q-atom/1", "q-desc": "q-desc/1", "q-term": "q-term/1"},
  "layer_mapping_version": "layers/1",
  "sources": {"sdd/specs/F1_ingest/spec.md": "sha256:<hex>"},
  "counts": {"nodes": 0, "terms": 0, "links": 0, "open_conflicts": 0, "by_status": {}},
  "id_counters": {"node": 42, "conflict": 3, "judgment": 321, "review": 7, "block": 123, "run": 11} }
```

**CT-4.2 — `conflicted_nodes.json`** (D9)
```json
{ "count": 2,
  "nodes": [ {"id": "N-000017", "family": "term:share_link", "layer": "L1",
              "source": {"file": "…", "lines": [5, 5]}, "conflict_ids": ["CF-000003"]} ] }
```
Sorted by id. Derived on every transaction; never edited.

**CT-4.3 — Query envelope**
```json
{ "query": "family", "args": {"term": "term:share_link"}, "graph_hash": "sha256:<hex>", "result": {} }
```

## 6. Acceptance criteria

> Tiers are provisional.

**Storage and determinism**
- **AC-4.1** *(sharding)* — **Given** nodes in families `term:a`, `(global)` and `null`, **when**
  written, **then** they are in `nodes/a.jsonl`, `nodes/_global.jsonl` and `nodes/_unplaced.jsonl`.
  → *unit.*
- **AC-4.2** *(family move)* — **Given** a node whose family changes from `term:a` to `term:b`, **when**
  the transaction commits, **then** it appears only in `nodes/b.jsonl`, and its outgoing links move to
  `edges/b.jsonl`. → *unit.*
- **AC-4.3** *(byte determinism)* — **Given** the same set of records written in two different orders,
  **then** every record file and `graph.meta.json` are byte-identical. → *property.*
- **AC-4.4** *(atomic)* — **Given** a transaction that fails validation on its last record, **then** no
  file under `.sdd/` changes. → *integration.*

**Consistency and registry**
- **AC-4.5** *(dangling link rejected)* — **Given** a link to a nonexistent node, **then** the
  transaction aborts with exit `4` naming the link. → *unit.*
- **AC-4.6** *(registry derived)* — **Given** an open conflict record with two members, **when**
  committed, **then** `conflicted_nodes.json` lists exactly those two nodes with their `conflict_ids`;
  **when** the record is resolved, **then** the registry is empty. → *integration.*
- **AC-4.7** *(membership enforced)* — **Given** a stored node missing a `conflict_ids` entry for an open
  record that lists it, **when** `sddc check` runs, **then** it reports the violation and exits `4`. →
  *unit.*
- **AC-4.8** *(check is complete)* — **Given** a store with one violation of each check in §4.3, **when**
  `sddc check` runs, **then** all eight are reported (the eighth, counters, was added by rel01 D24). →
  *integration.*

**Full form**
- **AC-4.9** *(node query)* — **Given** a node with incoming and outgoing links, **when**
  `sddc query node ID` runs, **then** stdout is a CT-4.3 envelope whose result holds the full record and
  both edge lists. → *contract.*
- **AC-4.10** *(neighbors)* — **Given** a chain A →refines→ B →refines→ C, **when**
  `query neighbors A --type refines --dir out --depth 2` runs, **then** B and C are returned with their
  paths. → *unit.*
- **AC-4.11** *(conflicts query)* — **Given** two open conflicts, **then** `query conflicts` returns the
  registry and both records with full member records. → *contract.*
- **AC-4.12** *(graph hash)* — **Given** two queries with no write between them, **then** `graph_hash`
  is equal; after any committed change, it differs. → *unit.*
- **AC-4.13** *(deleted nodes leave nothing behind)* — **Given** a node deleted per F2 §4.9, **when**
  any query runs, **then** it appears nowhere, no link references it, `sddc check` passes, and
  `id_counters.node` is unchanged (never rewound). → *integration.*

**Collapsed form**
- **AC-4.14** *(map)* — **Given** the worked-example graph (`design/rel01_design/core-working-principle.md` §9) with one conflicted L1 node in
  `term:share_link`, **when** `sddc map` runs, **then** that row's L1 cell shows its count with `✗`, and
  the row sorts first. → *golden.*
- **AC-4.15** *(family card)* — **Given** a family, **when** `sddc family TERM` runs, **then** members
  appear grouped by layer in layer order L0…L5, C, V, one line each. → *golden.*
- **AC-4.16** *(interlinked grouping)* — **Given** conflicts CF-1 {A, B} and CF-2 {B, C}, **when**
  `sddc conflicts` runs, **then** they are shown as one group. → *unit.*
- **AC-4.17** *(views regenerated and marked)* — **Given** any committed transaction, **then**
  `views/map.md`, the changed families' cards and `views/conflicts.md` match the CLI output — the same
  lines in the same order; a card keeps each claim's full text (D17) — and each starts with the
  do-not-edit header. → *golden.*
- **AC-4.18** *(forms agree)* — **Given** any graph, **then** the counts in `sddc map` equal the counts
  derivable from `query map` and from the node records. → *property.*

## 7. Decisions

- **D1 — One record, two derived forms** (implements D10). *Rejected:* separately maintained human and
  AI stores — they would drift.
- **D2 — Registry and conflict records are derived and validated on every transaction** (implements
  D9/D14). *Rejected:* updating the registry by hand in each writer — easy to forget.
- **D3 — ⚑ SQLite cache deferred;** indexes are built in memory on load. *Rejected for rel01:* a cache
  to invalidate before volumes need it.
- **D4 — ⚑ `_global.jsonl` and `_unplaced.jsonl`** for family `(global)` and `null`.
- **D5 — ⚑ Status marks** `✓ ? ~ · ✗` in text views, because colour is not available in every
  terminal or Markdown viewer (P-14 rule 5 adapted).
- **D6 — ⚑ `graph_hash` on every query** lets an agent detect a stale read.
- **D8 — ⚑ The run lock is `.sdd/run.lock`** (found while building T11). The M1 lock file was
  `.sdd/lock`, which collides with §4.1's judgment-lock folder `lock/`.
- **D9 — ⚑ Emptied shard files are deleted** in the same transaction, so a family that loses its last
  node leaves no stale file for the loader to read.
- **D10 — ⚑ The map lists real families first; `(global)` and `(no family)` close the table** (T14).
  They are not families, and sorting them by name put `(global)` between real families.
- **D11 — ⚑ A family card lists a constraint as "in scope" when its selector covers any member** — by
  the one rule F5's S3 uses, `sdd_compiler.model.scope.covers` (amended by F5 D9, I-57). Before that, by
  family, or any member's layer, term or category (T14). A constraint with an empty selector is not
  listed on every card. Found by reviewing the first golden file: a layer-scoped constraint was
  missing.
- **D12 — ⚑ A card line drops inline `*` and backtick marks, and reads a table row as cells**
  separated by `·` (T14, from reviewing R12's real cards; extended in R15, where rows became nodes).
  A node's `text` is the verbatim span and may begin inside `**Given**`; the human view shows the words.
- **D13 — ⚑ Card lines follow the source** — file, first line, id (M3 gate review). Sorting by id put
  `AC-5.13` before `AC-5.2` once criteria nodes carry their labels as ids (F2 D12).
- **D14 — ⚑ Constraints in scope are shown as lines, not bare ids** (M3 gate review). `sddc show` and
  `query node` are deferred (B2), so a bare id was a dead end in the CLI. The term's aliases head the card.
- **D15 — ⚑ A card shows `broader` both ways** — "Kind of: node" and "Narrower families: checked_node
  (1), …" (M3 gate review; F2 D16). The map is unchanged: rows and counts stay per family (AC-4.18).
  Shown instead of nesting families, because nesting would move counts and change F5's S1.
- **D16 — ⚑ An ambiguous line names why** — `? (referential, missing_actor)` (M3 gate review). On R12,
  18 of 43 nodes were `?`; a bare mark gives the reader nothing to act on.
- **D17 — The generated Markdown card keeps each claim whole; the terminal cuts at 80** (closes Q2,
  option b; owner 2026-09-19). The cut hid the point of long claims. AC-4.17's "match the CLI output"
  now means the same lines in the same order, with full text and linked ids.
- **D7 — ⚑ Interlinked conflicts are grouped** in the human view (rel01 D13: humans see several
  interlinked conflicts at once).

## 8. Open questions

- **Q1 — Are `.sdd/views/` committed to git or ignored?** Committed means readable on any git host
  without the CLI, at the cost of noisier diffs. Default: committed.
